1. backend/ — серверна частина

backend/api/main.py

Головний файл API на FastAPI. Тут описано 12 ендпоїнтів (адрес), які повертають дані: /api/kpi (показники), /api/trend (динаміка), /api/events (журнал подій), /api/units (підрозділи) тощо.

  • Усі SQL-запити параметризовані, тому SQL-ін'єкції неможливі.
  • Увімкнено CORS: фронтенд з іншого порту може звертатися до API.
backend/api/db.py

Підключення до PostgreSQL (бібліотека psycopg2): відкриває з'єднання, виконує запит, повертає результат і закриває з'єднання. Рядок підключення бере з .env.

backend/api/__init__.py

Порожній файл. Позначає для Python, що папка api — це пакет, тож можна писати from api.db import ....

backend/requirements.txt

Список бібліотек Python для бекенду: fastapi, uvicorn (сервер), psycopg2 (PostgreSQL), python-dotenv (читає .env). Усі встановлюються однією командою pip install -r requirements.txt.

backend/.env НЕ на GitHub

Секретний файл з паролем до бази (DATABASE_URL). Не потрапляє на GitHub завдяки .gitignore.

backend/.env.example на GitHub

Зразок .env без справжнього пароля. Інший розробник бачить, які налаштування треба заповнити.

2. backend/db/ — база даних

backend/db/schema.sql

Структура бази: 6 таблиць (regions, directions, event_types, units, events, frontline_points), зв'язки між ними (зовнішні ключі), індекси для швидкого пошуку і представлення (VIEW) v_events.

backend/db/seed.py

Генератор синтетичних (вигаданих) даних: 109 підрозділів, 1537 подій за 60 діб, умовна лінія. Записує .sql-файли й завантажує дані в базу.

backend/db/data.sql

Лише дані (команди INSERT), без структури.

backend/db/oko_dashboard.sql ДЛЯ ЗДАЧІ

Структура й усі дані одним файлом. З нього всю базу можна відновити однією командою psql.

3. frontend/ — клієнтська частина (у браузері)

frontend/index.html

Розмітка сторінки: шапка, фільтри, картки KPI, місце для карти, графіків і таблиці подій.

frontend/styles.css

Оформлення за брендбуком: темно-зелений #005a34 і жовтий #ffdd00, розташування блоків, адаптивність.

frontend/app.js

Логіка сторінки: бере дані з API (fetch), будує 7 графіків (Chart.js), карту OpenStreetMap (Leaflet) з умовними знаками APP-6D (milsymbol), обробляє фільтри, сортування й пагінацію.

frontend/config.js

Налаштування фронтенду: адреса бекенду (API_BASE). Якщо бекенд переїде на інший сервер чи порт, змінювати доведеться лише цей файл.

4. Файли в корені проєкту

.gitignore

Список файлів і папок, які Git не відстежує і не завантажує на GitHub. У нашому проєкті:

  • .env: містить пароль до бази, а секрети публікувати не можна;
  • .venv/, venv/: віртуальне середовище Python із сотнями МБ бібліотек; кожен створює його в себе з requirements.txt;
  • __pycache__/, *.pyc: тимчасові скомпільовані файли Python, які створюються автоматично.
Коротко: «щоб не викласти пароль і не засмічувати репозиторій файлами, які можна відтворити автоматично».
README.md

Опис проєкту: що зроблено, як запустити, список API. GitHub показує його на сторінці папки.

run.py

Скрипт запуску. Перевіряє підключення до бази й запускає сервери:

  • python run.py: обидва сервери;
  • python run.py backend: лише бекенд;
  • python run.py frontend: лише фронтенд.
ЗАПУСК.bat

Запуск подвійним кліком у Windows, без терміналу. Під час першого запуску відкриває налаштування, далі запускає run.py (обидва сервери).

5. Інші папки

scripts/setup_windows.ps1

Одноразове налаштування: знаходить PostgreSQL, питає пароль, створює .env, базу, віртуальне середовище й завантажує дані.

scripts/_env.ps1

Допоміжний скрипт: читає .env для PowerShell-скриптів.

scripts/smoke_test.py

Автоматична перевірка API: звертається до 10 ендпоїнтів і для кожного пише OK або FAIL. Smoke test — це швидка перевірка, що все загалом працює.

docs/

Скріншоти дашборда для README.

.venv/ НЕ на GitHub

Віртуальне середовище Python: окрема копія Python із бібліотеками саме для цього проєкту, щоб не конфліктувати з іншими проєктами.

__pycache__/ НЕ на GitHub

Кеш Python зі скомпільованими .pyc-файлами для швидшого запуску. Створюється автоматично, його можна видаляти.

6. Можливі питання викладача

Навіщо ділити на фронтенд і бекенд?

Кожна частина відповідає за своє: бекенд — за дані й безпечний доступ до бази, фронтенд — за відображення. Їх можна змінювати й розгортати окремо, а той самий API може обслуговувати інший клієнт (мобільний застосунок, інший сайт).

Чому браузер не бере дані з бази напряму?

Тоді пароль до бази був би в браузері, і будь-хто міг би його побачити. Бекенд стоїть посередині й віддає лише дозволені дані.

Що таке API і ендпоїнт?

API — набір адрес, за якими програма віддає дані. Ендпоїнт — одна така адреса: наприклад, /api/kpi повертає показники у форматі JSON.

Що таке CORS?

Правило браузера: сторінка з однієї адреси (порт 8080) не може брати дані з іншої (порт 8020), якщо сервер цього не дозволив. У бекенді CORS увімкнено, тобто фронтенду це дозволено.

Що таке JSON?

Текстовий формат обміну даними, наприклад {"total_events": 1537, ...}.

Де подивитися всі ендпоїнти?

http://localhost:8020/docs — автоматична документація Swagger, яку генерує FastAPI. Там кожен запит можна виконати кнопкою.

Звідки дані?

Їх згенерував скрипт seed.py, тобто вони синтетичні. Реальних даних у проєкті немає.

Чому .env не на GitHub, а .env.example є?

У .env справжній пароль, а це секрет. .env.example — лише шаблон, з якого видно, які налаштування потрібні.

Як захищено від SQL-ін'єкцій?

Значення з фільтрів не вставляються в текст SQL, а передаються окремо як параметри (%s). Для сортування діє білий список дозволених стовпців.
