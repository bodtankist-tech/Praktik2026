ШПАРГАЛКА: ДЛЯ ЧОГО КОЖНА ПАПКА І ФАЙЛ (дашборд «ОКО»)
================================================================

ЗАГАЛЬНА СХЕМА (сказати першим)
----------------------------------------------------------------
  PostgreSQL  ->  БЕКЕНД (Python, FastAPI)  ->  ФРОНТЕНД (HTML/CSS/JS)
     база           порт 8020, віддає JSON        порт 8080, браузер

  "Проєкт розділено на бекенд і фронтенд. Бекенд бере дані з бази
   PostgreSQL і віддає їх через API у форматі JSON. Фронтенд - це
   сторінка в браузері, яка звертається до API і малює графіки й карту.
   Вони працюють як два окремі сервери на різних портах."


================================================================
1. ПАПКА backend/  - СЕРВЕРНА ЧАСТИНА
================================================================

backend/api/main.py
  Головний файл API на FastAPI. Тут описані ендпоїнти (адреси), які
  повертають дані: /api/kpi (показники), /api/trend (динаміка),
  /api/events (журнал подій), /api/units (підрозділи) тощо - 12 штук.
  Усі SQL-запити параметризовані -> захист від SQL-ін'єкцій.
  Увімкнено CORS - дозволяє фронтенду з іншого порту звертатися до API.

backend/api/db.py
  Підключення до PostgreSQL (бібліотека psycopg2). Відкриває з'єднання,
  виконує запит, повертає результат і закриває з'єднання.
  Рядок підключення бере з файлу .env.

backend/api/__init__.py
  Порожній файл. Позначає для Python, що папка api - це пакет,
  щоб можна було писати "from api.db import ...".

backend/db/schema.sql
  Структура бази: 6 таблиць (regions, directions, event_types, units,
  events, frontline_points), зв'язки між ними (зовнішні ключі),
  індекси для швидкого пошуку і представлення (VIEW) v_events.

backend/db/seed.py
  Генератор синтетичних (вигаданих) даних: 109 підрозділів,
  1537 подій за 60 діб, умовна лінія. Записує .sql-файли і
  завантажує дані в базу.

backend/db/data.sql
  Лише дані (команди INSERT), без структури.

backend/db/oko_dashboard.sql
  ГОЛОВНИЙ ФАЙЛ ДЛЯ ЗДАЧІ: структура + всі дані одним файлом.
  Можна відновити всю базу однією командою psql.

backend/requirements.txt
  Список бібліотек Python, які потрібні бекенду:
  fastapi, uvicorn (сервер), psycopg2 (PostgreSQL), python-dotenv (.env).
  Встановлюються однією командою: pip install -r requirements.txt

backend/.env
  СЕКРЕТНИЙ файл з паролем до бази (DATABASE_URL).
  НЕ потрапляє на GitHub (див. .gitignore).

backend/.env.example
  Зразок файлу .env без справжнього пароля. Потрапляє на GitHub,
  щоб інший розробник знав, які налаштування треба заповнити.


================================================================
2. ПАПКА frontend/  - КЛІЄНТСЬКА ЧАСТИНА (те, що в браузері)
================================================================

frontend/index.html
  Розмітка сторінки: шапка, фільтри, картки KPI, місце для карти,
  графіків і таблиці подій.

frontend/styles.css
  Оформлення за брендбуком: темно-зелений #005a34 і жовтий #ffdd00,
  розташування блоків, адаптивність.

frontend/app.js
  Логіка сторінки: звертається до API (fetch), будує 7 графіків
  (Chart.js), карту OpenStreetMap (Leaflet) з умовними знаками
  APP-6D (milsymbol), обробляє фільтри, сортування і пагінацію.

frontend/config.js
  Налаштування фронтенду: адреса бекенду (API_BASE).
  Якщо бекенд переїде на інший сервер чи порт - змінюється лише тут.


================================================================
3. ФАЙЛИ В КОРЕНІ ПРОЄКТУ
================================================================

.gitignore
  Список файлів і папок, які Git НЕ має відстежувати і завантажувати
  на GitHub. У нашому проєкті:
    .env          - містить пароль до бази, секрети не можна публікувати;
    .venv/, venv/ - віртуальне середовище Python (сотні МБ бібліотек),
                    його кожен створює у себе з requirements.txt;
    __pycache__/, *.pyc - тимчасові скомпільовані файли Python,
                    створюються автоматично, у репозиторії не потрібні.
  Коротко: "щоб не викласти пароль і не засмічувати репозиторій
  файлами, які можна відтворити автоматично".

README.md
  Опис проєкту: що зроблено, як запустити, список API.
  GitHub показує його на головній сторінці папки.

run.py
  Скрипт запуску. Перевіряє підключення до бази і запускає:
    python run.py           - обидва сервери;
    python run.py backend   - лише бекенд;
    python run.py frontend  - лише фронтенд.

ЗАПУСК.bat
  Запуск подвійним кліком у Windows, без терміналу. Перший раз
  запускає налаштування, далі - run.py (обидва сервери).


================================================================
4. ІНШІ ПАПКИ
================================================================

scripts/setup_windows.ps1
  Одноразове налаштування: знаходить PostgreSQL, питає пароль,
  створює .env, базу, віртуальне середовище і завантажує дані.

scripts/_env.ps1
  Допоміжний: читає .env для PowerShell-скриптів.

scripts/smoke_test.py
  Автоматична перевірка API: звертається до 10 ендпоїнтів і пише
  OK або FAIL. ("Smoke test" - швидка перевірка, що все "не димить".)

docs/
  Скріншоти дашборда для README.

.venv/  (в Git не потрапляє)
  Віртуальне середовище Python: окрема копія Python із бібліотеками
  саме для цього проєкту, щоб не конфліктувати з іншими проєктами.

__pycache__/  (в Git не потрапляє)
  Кеш Python: скомпільовані .pyc-файли для швидшого запуску.
  Створюється автоматично, можна видаляти.


================================================================
5. МОЖЛИВІ ПИТАННЯ ВИКЛАДАЧА
================================================================

Навіщо ділити на фронтенд і бекенд?
  Кожна частина відповідає за своє: бекенд - дані і безпека доступу
  до бази, фронтенд - відображення. Їх можна змінювати і розгортати
  окремо; той самий API може обслуговувати інший клієнт
  (мобільний застосунок, інший сайт).

Чому браузер не бере дані з бази напряму?
  Тоді пароль до бази був би у браузері, і будь-хто міг би його
  побачити. Бекенд стоїть посередині і віддає лише дозволені дані.

Що таке API / ендпоїнт?
  API - набір адрес, за якими програма віддає дані. Ендпоїнт - одна
  така адреса, наприклад /api/kpi повертає показники у форматі JSON.

Що таке CORS?
  Правило браузера: сторінка з одного адреса (порт 8080) не може
  брати дані з іншого (порт 8020), якщо сервер цього не дозволив.
  У бекенді ввімкнено CORS - дозвіл для фронтенду.

Що таке JSON?
  Текстовий формат обміну даними: {"total_events": 1537, ...}.

Де подивитися всі ендпоїнти?
  http://localhost:8020/docs - автоматична документація Swagger,
  її генерує FastAPI. Там кожен запит можна виконати кнопкою.

Звідки дані?
  Синтетичні, згенеровані скриптом seed.py. Реальних даних немає.

Чому .env не на GitHub, а .env.example є?
  У .env справжній пароль - секрет. .env.example - лише шаблон,
  щоб було видно, які налаштування потрібні.

Як захищено від SQL-ін'єкцій?
  Значення з фільтрів не вставляються в текст SQL, а передаються
  окремо як параметри (%s); для сортування - білий список стовпців.
