# Мережеве планування — інтерактивний тренажер

**Дисципліна:** Системи та методи підтримки прийняття рішень  
**Тема 3:** Застосування методів теорії мережевого планування й управління для обґрунтування рішень в органах військового управління  
**Заняття 2:** Задача розрахунку мережевого графіку

## Запуск

1. Розпакуйте ZIP-архів.
2. Відкрийте `index.html` подвійним кліком у сучасному браузері (Chrome, Firefox або Edge).
3. Інтернет, сервер, реєстрація та сторонні JavaScript-бібліотеки не потрібні.

## Що можна робити

- **Маршрут навчання** — шість покрокових етапів.
- **Конструктор** — редагувати назви робіт, тривалість, початкову та кінцеву події; додавати/видаляти роботи та події.
- **Прямий прохід** — покроково отримувати ранні строки `E` і перевіряти власні відповіді.
- **Зворотний прохід** — обчислювати пізні строки `L` та перевіряти їх.
- **Критичний шлях** — таблиця `ES, EF, LS, LF, R` і сценарій «Що, якщо?».
- **Практикум** — п’ять завдань із миттєвою перевіркою і поясненнями.
- **Інфографіки** — 10 окремих фотореалістичних ілюстрацій із переглядачем.
- **Експорт** — збереження мережі в JSON, результатів у CSV і зображення SVG; повторний імпорт JSON.

## Правила обчислення

Застосовується модель AOA — роботи на стрілках, події у вузлах.

Для кожного спрямованого ребра `(i, j)` з тривалістю `tᵢⱼ`:

- прямий прохід: `E[start] = 0`, `E[j] = max(E[i] + tᵢⱼ)`;
- зворотний прохід: `L[finish] = E[finish]`, `L[i] = min(L[j] - tᵢⱼ)`;
- ранній початок `ES = E[i]`;
- раннє завершення `EF = E[i] + tᵢⱼ`;
- пізнє завершення `LF = L[j]`;
- пізній початок `LS = L[j] - tᵢⱼ`;
- повний резерв `R = LS - ES = LF - EF`.

Для базового прикладу `A(3), C(4), E(2)` утворюють критичний шлях тривалістю **9 днів**. Нижня гілка `B(2), D(3), F(3)` триває **8 днів** і має повний резерв **1 день** для кожної роботи за цієї двогілкової схеми.

### Обмеження конструктора

- Від 2 до 14 подій та до 40 робіт.
- Одна початкова та одна кінцева подія.
- Ациклічна мережа; кожна подія має належати до мережі.
- У демонстраційній моделі між двома подіями допускається лише одна робота. Для паралельних робіт використовуйте різні події.
- Підтримуються додатні числові тривалості до 365 днів.
- Немає обліку ресурсних обмежень, невизначених тривалостей PERT, календарних вихідних, фіктивних робіт або лагів. Результати є CPM-розрахунками для заданої моделі.

## Структура

- `index.html` — розмітка
- `styles.css` — адаптивний дизайн
- `app.js` — логіка графіка, CPM, уроків і практикуму
- `assets/infographics/` — 10 інфографік та їхні мініатюри

**Примітка:** згенеровані інфографіки є ілюстраціями; окремі дрібні написи чи цифри на зображеннях можуть бути неточними. Для демонстрації математично правильного розрахунку орієнтуйтеся на живий графік та таблицю результатів тренажера.
